# v0.2 Plan

## Theme

Make `mcpxray check <url>` **actually useful for the common case.** Today a
random MCP server is (a) usually TypeScript, which returns ⚪ UNKNOWN, and
(b) when checked by URL, scanned whole-repo (tripping on test fixtures).
v0.2 closes both gaps and deepens the ruleset.

Current baseline: **commit `99a615e`** on `main`, 123 tests, `check` + verdict
shipped (Python static only).

---

## Work items (priority order)

### 1. Scope URL clones to the server entry point — *accuracy*

**Problem.** `check https://github.com/owner/repo` clones the *whole* repo and
runs the extractor over every `.py` — including `tests/`, `docs_src/`, fixtures.
Live demo on `modelcontextprotocol/python-sdk`: 420 "tools", 34 "secrets", score
0 — almost all of which are fake keys in test fixtures. For a single-purpose
server repo the signal is clean; for a big/SDK repo it over-scans.

**Approach.** After cloning, locate the *server* source instead of scanning
everything. Heuristics, in order:
1. `[project.scripts]` / entry point declared in `pyproject.toml`;
2. the directory that actually contains `@mcp.tool` / tool registrations;
3. `src/`;
4. fall back to repo root (current behavior).

Add a `--scope <rel-path>` override. Make `scan`/`score` adopt
`resolve_target` too (today only `check` does). Files: `source.py`
(a `_scope_path(repo_root) -> Path` step after clone), `cli.py`.

**Acceptance.** `check https://github.com/modelcontextprotocol/python-sdk`
scopes to a server dir, not the whole tree; test-fixture false positives drop
materially; a single-purpose server repo is unaffected.

### 2. TypeScript static extractor — *coverage (the big win)*

**Problem.** Most MCP servers are TypeScript; today they return ⚪ UNKNOWN with
a "give us a manifest" hint. That's the majority case failing.

**Approach.** A new `TsExtractor` (`extract/typescript_static.py`) mirroring
`PythonExtractor`: walk `.ts`/`.js`, find tool registrations — the TS SDK's
`server.tool("name", {schema}, handler)` / `@tool` decorator form, and the
lowlevel `server.setRequestHandler(ListToolsRequestSchema, …)`. Lift name +
description + Zod/raw schema → `input_schema`. **No execution.**

Reuses the IR + rules unchanged; MCP102 (secrets) and MCP103 (RCE) already
scan any source text via `McpServer.sources`. `extractor_for` picks the first
matching extractor, so just registering `TsExtractor` makes `check`/`scan`
work for TS. Files: `extract/typescript_static.py` + tests + TS fixtures.

**Acceptance.** A real TS server (e.g. a `modelcontextprotocol/servers`
example) returns a real 🟡/🔴 verdict, not UNKNOWN.

### 3. Rules MCP105 + MCP109 — *depth*

- **MCP105 — schema/implementation drift (warning):** a tool's declared
  `inputSchema` disagrees with its handler (param in schema but not code, or
  vice-versa). Both halves are already in the IR for Python; feasible
  statically once TS lands.
- **MCP109 — transport auth / TLS (warning):** insecure transport setup
  (SSE/HTTP without TLS or auth). Pattern-match the server's transport
  construction in source.

Files: `rules/builtin/schema.py` (MCP105), `rules/builtin/transport.py`
(MCP109, new).

### 4. Runtime `tools/list` capture — *any-language accuracy (opt-in)*

**Problem.** Static extraction can miss dynamically-registered tools.

**Approach.** An opt-in `check <url> --runtime` that spawns the server in a
sandbox, calls `tools/list`, feeds the dump to `ManifestExtractor`. Heavier and
needs sandboxing — opt-in, never the default. Replaces the manual `--manifest`
step for the UNKNOWN case. Files: a new `runtime.py`, `cli.py`.

## Out of scope (→ v1.0)

Hosted badge API + public leaderboard (infra); `--fix` for trivial rules;
pre-commit hook; PyPI trusted publishing; registry integrations
(Glama/Smithery); frozen plugin API (semver).

## Sequencing

1. **Scope-clone refinement** — quick win; unblocks accurate Python URL checks.
2. **TS extractor** — biggest user-visible win; makes `check` useful for the
   majority of servers.
3. **MCP105 + MCP109** — depth, built on the extractors.
4. **Runtime capture** — opt-in power feature.
